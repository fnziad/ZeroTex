# ZeroTeX Contributor Instructions

## Product contract

ZeroTeX is a local-first, source-available resume builder. Core resume creation must remain usable without an account. Resume content must not be sent to analytics, logs, or external services unless the user deliberately invokes a clearly labeled external flow.

The versioned document contract in `lib/resume-document.ts` is the persistence source of truth. Application versions and document schema versions are independent; schema changes require migrations and round-trip tests.

## Stack

- Next.js 16 App Router
- React 19 and TypeScript 5
- Tailwind CSS and Radix-based UI primitives
- pnpm 11 on Node.js 22+
- Vitest for unit tests
- Vercel for preview and production deployments

## Architecture

- `app/` contains routes and server/client boundaries.
- `components/resume/` contains editing, section management, preview, and export UI.
- `lib/resume-types.ts` defines resume data structures.
- `lib/resume-document.ts` validates, migrates, serializes, and persists portable documents.
- `lib/latex-generator.ts` is the deterministic LaTeX output path.

## Change rules

- Preserve local-first behavior and migration compatibility.
- Validate untrusted files before rendering or persistence; retain size and nesting limits.
- Use explicit TypeScript unions instead of adding new `any` payloads.
- Keep LaTeX, live preview, and print output aligned for every section change.
- Do not use raw HTML injection for resume content.
- Keep interactive components keyboard accessible and usable at mobile widths.
- Prefer server components unless browser state or events require a client boundary.
- Update `README.md`, `CHANGELOG.md`, `ROADMAP.md`, and `package.json` together for releases.

## Required checks

```sh
pnpm install --frozen-lockfile
pnpm run lint
pnpm run typecheck
pnpm run test
pnpm run build
```

Changes to persistence, imports, exports, templates, or editor history also require focused regression fixtures and browser-level verification.
